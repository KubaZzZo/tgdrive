# CDN 与多线路调度

CDN 可以改善浏览器与 VPS 之间的线路。文件仍经 Telegram → VPS → CDN → 浏览器传输；首次读取和绕过缓存的媒体请求仍消耗 VPS 流量，Telegram 回源也可能限制速度。

本文只使用示例域名和占位配置。CDN 供应商、节点、配额和当地网络需要自行核实。

## 先接测试域名

1. 使用独立测试域名，例如 `drive-test.example.com`，保留正式域名原有解析。
2. 在 CDN 添加域名，源地址指向 VPS，回源使用 HTTPS 和正确的 Host/SNI。回源地址应能直接到达源站，避免解析回同一 CDN 形成循环。
3. 签发并验证边缘证书，同时验证源站证书；不要关闭证书校验。可先通过 DNS 验证签发，再切换网站解析。确认边缘与源站证书的续期方式。
4. 将测试域名解析至供应商要求的 CNAME。若使用另一家 DNS 服务商托管记录，应按目标 CDN 的要求决定是否开启额外代理，避免无意叠加两层 CDN。
5. 使用相同网络对比直连与 CDN，再决定是否切正式域名；保留原记录的类型、目标、代理状态和 TTL 用于回退。

只调整本项目的域名和匹配规则，不覆盖共享反向代理或修改其他站点。

## 缓存与会话

| 路径 | 策略 |
|---|---|
| `/assets/*` | 文件名带哈希，可遵循源站长期缓存 |
| `/` | 遵循源站，不强制长期缓存首页 |
| `/api`、`/api/*` | 绕过共享缓存，保留 Cookie、Set-Cookie 和鉴权 |
| `/s`、`/s/*` | 绕过缓存，每次回源检查分享是否撤销或过期 |

禁止对全站或带会话的响应强制缓存。私有路径应返回 `Cache-Control: private, no-store`，并在 CDN 配置明确的绕过规则。仓库的 `Caddyfile` 会在响应写出时覆盖私有路径的缓存头，防止分享下载的上游缓存头覆盖该策略。

如果历史上缓存过私有内容，添加绕过规则不会自动清除旧副本；应使用服务商的缓存清理功能处理对应路径。

## 视频与上传

- 保留 `Range`、`206`、`Content-Range`、`Content-Length`，不要压缩或转换媒体响应。
- 关闭完整请求体和源响应缓冲，确保及时转发媒体、取消请求和上传分片；设置适合长时间传输的超时。
- 确保 GET、HEAD、POST、PATCH、DELETE 及 `Upload-Offset`、`X-Workspace-ID` 可以正常透传。
- 单请求体上限应覆盖实际上传分片大小。大文件总大小与 CDN 的单请求限制是不同概念，仍需验证分片上传和续传。
- 保持 API 与页面同源。若另设媒体域名，需要同步处理 Cookie、CORS、播放器和分享 URL。

Caddy 默认不配置完整请求/响应缓冲，`flush_interval -1` 用于即时刷出数据。其他代理应使用各自支持的指令，不要将 Nginx 的缓冲开关直接套用到 Caddy。

## 多 CDN 地域调度

先逐家验证同一站点域名的证书、健康检查、鉴权、Range 和上传，再加入候选池。候选池包含多家服务商，不表示这些服务商的带宽可以叠加。

支持地域线路和探针的 DNS 调度服务可按以下方式组织：

- 为大陆和境外分别选择当地测点；有足够测点时再细化到省份、运营商或国家。
- 经由每个候选 CDN 访问正式域名的 `/api/health/ready`，同时检查边缘证书和真实应用回源。
- 启用健康优选与异常剔除；地域池不可用时配置回落线路，并验证全池故障行为。
- 根据需求设置拨测间隔和 TTL。探针优选、DNS 缓存、递归解析器及客户端子网信息都会影响切换效果，不是每个 HTTP 请求即时重选。

健康检查响应快不代表持续视频带宽充足。选择媒体线路时，还要评估套餐带宽上限、流量配额、丢包、首帧和大文件吞吐；不宜仅按地理距离或单次延迟判断。

用候选 CNAME 做旁路验收时，可用 `curl --connect-to` 指定连接目标，同时保留正式域名的 Host、TLS SNI 和证书校验。先验收匿名媒体返回 401，再用登录态从一条线路读取媒体前半段，拿它的 ETag 作为另一条线路续读时的 If-Range。对比 206、Content-Range、ETag 和样本内容。DNS 调度影响后续连接，活跃请求的重试仍会受浏览器 DNS 和连接复用影响。
估算拨测请求量：候选数 × 测点数 × 每日拨测次数。确认请求、流量与探针的收费规则。

## 上线验收与回退

- HTTPS 与健康检查通过，浏览器能正常打开页面。
- 匿名文件列表和下载返回 401；登录后可以访问，私有响应不出现缓存命中。
- 视频头部、尾部、中间及跨消息区间的 GET 返回正确 206，内容长度与哈希一致，无媒体压缩；浏览器拖动到未缓冲位置可以播放。
- 验证一次真实分片上传、续传状态和取消清理，使用专门的临时测试数据。
- 在无登录窗口验证分享，并检查撤销或过期后的访问；只操作自己的测试分享。
- 从用户实际网络测量页面、起播、拖动和持续下载，记录完整下载与超时样本，避免将代理出口或 VPS 本机结果当作用户速度。
- 切换正式域名后通过普通 DNS 复测；预检时的指定节点请求不能代替最终验证。

回退时恢复该域名原记录的类型、目标、代理状态和 TTL，等待缓存更新并验证访问。切换时保留原代理或隧道服务，验证完成前不要删除回退资源。

## 隐私与记录

运行日志、截图、Cookie、测试报告、个人域名、IP、账号标识与隧道配置应留在本机。将实际记录放入被忽略的 `docs/local/` 或 `output/`；提交前检查暂存文件及新增提交，不要直接将整个工作区暂存。
`.env`、会话文件、数据库和证书私钥不得提交。公共示例统一使用 `example.com` 等占位值，仓库文档只保留通用步骤。
